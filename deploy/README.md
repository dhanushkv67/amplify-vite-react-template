# HTTPS client-demo runbook (not a production-readiness claim)

Set `SITE_DOMAIN` to a DNS name pointing at this host and set a unique `POSTGRES_PASSWORD` in a private `.env` (do not commit it). Allow inbound 80/443 for Caddy certificate issuance. From the repository root run `docker compose -f deploy/compose.https.yaml up --build -d`; Caddy terminates TLS, forwards `/api/*` to the private API and the remainder to the private web service. The database volume and Caddy certificate storage survive ordinary restarts. Do not set `DEMO_SEED` or use demo credentials in this stack. `NODE_ENV=production` refuses demo seeding; `APP_ORIGIN=https://<domain>` enforces browser origin and Secure, HttpOnly, SameSite=Lax cookies.

Before any client demo, check the actual certificate chain and hostname in a browser, verify HTTPS-only login, signup and API traffic in network tools, inspect mixed-content warnings, exercise expiry/revocation and cross-project denial, restart the stack and confirm persisted tasks/comments. These checks have not been performed on a target host; DNS, certificates, secrets, backup/uptime/capacity policy and deployment sign-off are operator responsibilities. Never present config alone as evidence of a verified deployment.
